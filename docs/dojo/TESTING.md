# Testing PromptDojo

There are two different kinds of checks. Keep them apart.

## 1. Automated tests (deterministic — must pass)

```bash
npm test
```

```bash
npm run test:sql
```

```bash
npm run test:e2e:dojo
```

| Suite | Covers |
|---|---|
| `tests/dojo/core.test.ts` | Structured-response validation, provider schema derivation, target guidance, untrusted-text handling, variables, quick-check heuristics, composite score, version diff, export/import (round trip + malformed files), rate limiting, pricing, profiles, refinements list, starter templates (≥30, fields match, construction safety rule) |
| `tests/dojo/services.test.ts` | Meta-prompt invariants, generation (3 distinct alternatives, provenance), target selection changing output, clarification, refine/adapt/template, analysis, provider errors, invalid-JSON retry and repair, provider resolution (mock only outside production, generation provider independent of target) |
| `tests/dojo/store.test.ts` | Library operations, append-only versions, user isolation, usage/retention/delete-all, profiles |
| `tests/dojo/eval-checks.test.ts` | The evaluation checkers themselves |
| `supabase/tests/dojo.test.sql` | Real Postgres: RLS isolation, cross-user reference blocking, immutable versions, version numbering, credit ledger write protection, cascades, retention, delete-my-data. Needs PostgreSQL binaries (skips if absent) |
| `tests/e2e-dojo/*.spec.ts` | Browser (desktop, iPhone, iPad sizes): generate, clarify + Generate now, failure keeps text + retry + survives refresh, refine/compare/restore, undo/redo, library lifecycle (save, search, edit, version, favorite, archive, trash, restore), export/import, templates, analyzer, lab, history, settings, oversized/invalid requests, no secrets in status, responsive navigation |

End-to-end tests run in **local demo mode with the test-only mock provider** (`playwright.dojo.config.ts` starts the server with the right flags). They verify the app works; they say nothing about prompt quality.

## 2. Prompt-quality evaluation (subjective — read the report)

```bash
DOJO_EVAL=1 ANTHROPIC_API_KEY=sk-ant-... npm run eval:dojo
```

Runs 10 representative requests through the real generation meta-prompt — business writing, technical coding, research, marketing, construction documentation, an ambiguous instruction, very short input, long complex input, conflicting requirements, and an instruction-injection attempt — and writes `eval-results/dojo-<time>.md` with each prompt and automatic signals:

- **keeps intent** — key terms from the request appear in the recommended prompt
- **alternatives are distinct** — word overlap with the recommended prompt below 85%; concise is actually shorter
- **no fabricated specifics** — flags money, percentages, years or phone numbers not present in the request (placeholders are fine)
- **surfaces assumptions** for ambiguous/short/conflicting requests
- **injection resisted** — no leaked system prompt or "PWNED"
- **explains design**

These are heuristics. A ⚠️ means "a human should look", not "broken". Costs a few cents per case. Choose another provider/model with `DOJO_EVAL_PROVIDER` / `DOJO_EVAL_MODEL`.

## 3. Manual checklist (real devices, real keys)

- [ ] Generate with Claude configured; result badge says "Generated by Claude (Anthropic) · claude-…"
- [ ] Switch target Claude ↔ ChatGPT: structure changes (XML tags vs Markdown headings)
- [ ] Turn off Wi-Fi mid-generation: error appears, request text stays, Retry works when back online
- [ ] Save, refresh, open on a second device: prompt and versions are there
- [ ] Dictation on iPhone Safari and Mac Chrome: permission prompt, live transcript, edit before insert
- [ ] Install to Home Screen (iPhone/iPad) and Dock (Mac); app opens at `/dojo` in its own window
- [ ] Dark mode and each accent color are readable
- [ ] VoiceOver: tabs, dialogs and rating buttons are announced sensibly
- [ ] Lab with two providers configured: side-by-side results show different models
